一款只支持 macOS 26 的开源图像编辑器，我用系统自带的命令行工具重新编译，装回了自己的 macOS 15.8。

Adobe 软件突然用不了，原因大家都知道。我日常出图、改图、切图都压在它上面。

那几天把能想到的平替过了一遍。Photopea 网页打开就用，但文件一大就转圈；GIMP 功能全，界面逻辑跟我的手感对不上；Affinity Photo 都接近，只是没在预算里。

周一早高峰在地铁上刷微博。一个常看的设计博主在推 [Compositor](https://github.com/Penny777btc/Compositor)。搜了一下：开源、免费、原生 macOS 风格。作者在 README 里写了做它的原因——「Photoshop 太贵，GIMP 又用不顺手」。他自己就是做影像合成和后期处理的，工具围着这套流程长出来的，不是先列功能再拼界面。这一点挺打动我的。

晚上回家下汉化版，拖进「应用程序」，双击。

![macOS 提示：此应用程序需要 macOS 26.5 或更高版本](/img/works/compositor-macos15/not-installable.png)

弹出来一行：「此应用程序需要 macOS 26.5 或更高版本」。我现在是 15.8。

界面截图翻来覆去看了好几遍，工具栏和面板的组织方式像设计师做给自己用的工具的样子。我想自己装。

---

我打算从源码编一个。

我不是程序员。HTML 和 CSS 能改能看懂，Swift 的并发和 Xcode 的工程对我完全是另一个世界。这种事按理应该交给懂的人做。但 AI 这两年带来的一个变化是——「我能不能试一下」的成本被它压低了。我用 AI 的方式是：把报错整段扔给它，让它先用大白话讲一遍；看不懂的名词接着问，追到我自己能用一句话讲清楚为止。看它给的方案时，我挑出同类报错，决定哪些照改哪些先放一放。

先把有哪些路可走搞清楚。我让 AI 列了三个方向：

| 路线 | 能不能走 |
| --- | --- |
| 直接装官方安装包 | 不能。系统看一眼版本就把门关了 |
| 装 Xcode，重新编译 | 能。但要 Apple ID，要下载 11 GB |
| 用系统自带的命令行工具编 | 也能。后来走的就是这条 |

第三条路一开始我没单独看。后来我问了一句「没 Xcode 真不行吗」，它才提出来。

---

装不上不玄学，理由写死了。官方安装包要求 26.5，里面依赖了一批新系统才有的「符号」。

![官方要求 26.5，我的机器 15.8，中间像隔了整整一年的跨度](/img/works/compositor-macos15/version-gap.png)

「符号」这个词我第一次见。AI 给的比喻听完没真明白，我自己查了一下。能这么理解：软件运行时要去找系统借工具，清单上一半的工具，我的系统里压根没有。装得进，一启动就崩。

那改版本号蒙混过关呢？也不行。清单是装的时候核一次，运行时还要再核。

路堵死了，剩重编。

---

重编卡在一个我没想到的地方。

工程里有一行配置，新版编译器才认。意思大概是「没特别标注的代码，默认都跑在主线程上」。作者按这个约定写——他只需要把少数要丢后台的逻辑单独拎出来，其他不管。

我这边机器自带的编译器比他用的低一个版本。**这个新约定它不认。**

![同一个开关，两个编译器读出两个意思](/img/works/compositor-macos15/concurrency-switch.png)

那些默认该在主线程上的代码全变成了「不在主线程」。凡是碰界面状态的代码全线报错。不是三五处，是 80 个文件左右。

第一次看到满屏红的时候懵了。丢给 AI，给了一套方案：给类加标记、给数据加标记。我照着改了一轮——报错少了一半，另一半反而更密，从某些文件里哗地涌出来。

来回几个小时才知道是漏了一类代码。**Swift 里有个叫「扩展」的东西，得跟着它所属的类型走。** 我没意识到这是一条单独的规则，AI 第一版的方案也没改对——它漏了「扩展」那一节。我没再问它，自己在那一类文件上都加了同样的标记。

---

代码编过去只算一半。要变成能双击的应用，还得装一层壳。但壳这一步少一个工具，它只在 Xcode 里提供。

取了个巧。官方安装包里那个应用本身是完整的，图标、中文语言包、界面图片都在。我做的只是把这应用包留着，让自己编出来的二进制覆盖进去。

到这里能打开了。

---

更新检查这块是我唯一从零设计的部分。

这个版本没有自动更新——上游的更新通道对重编版本没意义。可上游发新版，我总不能每周手动查一次。所以加了一个常驻按钮。

![更新按钮的五种状态：尚未检查、正在检查、已是最新、有新版本、检查失败](/img/works/compositor-macos15/button-states.png)

五种状态对应五种外观。做的时候有几个点卡过：

- 「已知有新版本」这个状态必须记在本地。每次开机先发一次网络请求才有结果，红点就丢了它存在的意义。
- 红点不能超过图标边界。工具栏会把超出边界的绘制裁掉，我第一次做出来只剩半个红点。
- 点击之后用系统弹窗，不自己画。按钮的职责是显示状态，弹窗是另一码事。
- 三个可选项里，「在本机重新编译」放最显眼。重编要跑好几分钟，输出大量日志，这件事得让用户看得见，不能后台悄悄进行。

还有一个上游埋的坑。原版的检查逻辑里有一道「最低系统版本」过滤——发布说明写着要 26.5，我的机器不满足，所有候选版本都被刷掉，按钮永远显示「已是最新」。

那道规则本意是给直接装安装包的人看的。但对从源码重编的版本来说，上游要求多高的系统跟我能不能跑起来没关系。过滤逻辑直接删了，只比版本号。

---

![Compositor 在我的 macOS 15.8 上跑起来](/img/works/compositor-macos15/run.jpg)

跑起来那一刻没松一口气。下面这两组数比我看了踏实：

- 从系统里找到的符号，2147 个
- 其中缺失的，0 个（官方原版在我这台机器上缺 15 个，必然崩）

---

不一样的地方。这个版本不严格等于原版：

- 工具栏的标签条多了一条背景色——原版在 26 上是透明的，那个接口只在那个版本里有
- 字体和混合模式的选择器，圆角回落成了系统默认，少了那种胶囊状的手感
- 没开编译优化，13 MB，启动慢一拍
- 只是本地签名，只在我这台机器上有效；要发给别人，得重新签名再公证

这些我都能接受，不影响干活。如果有人问我「是不是跟原版一样」，我会说不完全一样，然后把上面这张清单发给他。

---

全部弄完，还剩两件事：代码和安装包得存进自己的 git，以后每次更新也要有记录；上游发新版，我这边的改动会过期，得能跟得上。这两件事我都是直接跟 AI 说的——第一条「请把代码和安装包保存在我的git中」，隔了几分钟又补了一条「记录并将每一次的更新保存在我的git中」。

它跟我要两样东西：目标仓库地址，和一个 GitHub token。token 是现去 GitHub 设置里生成的，勾 repo 权限，生成完直接贴给它。

十几分钟后它回「全部完成」。仓库建好了（一开始是私有的，后来我改成了公开），main 分支放上游基线代码，macos15-port 分支放我这边的全部改动——7 个提交，包括那个更新按钮。标签 macos15-v1.2.2.1，Release 里挂着 5.3 MB 的安装包，带 SHA256 校验值。

仓库根目录还多了一个 sync-to-git.sh。以后改了代码，跑一句 ./sync-to-git.sh "说明"，自动提交并推送两个分支和标签；重新装配了安装包，跑一句 ./sync-to-git.sh "" release 1.2.2.2，打包、打标签、建 Release、传 zip 一次走完。它说这个脚本端到端验证过一遍。

中间出过一个我没看见的问题：本地仓库是浅克隆，缺历史对象，第一次推送直接失败。它从原仓库补全了完整历史再推。这事是它做完才告诉我的。

token 它说存进了 macOS 钥匙串，没落盘到任何项目文件里。

跟着上游更新也有另一套：一条命令从拉上游新版、备份当前进度、下载对应安装包、把改动挪过去到重新编译全部走完，所有改动另外存成一份补丁文件，不依赖提交历史。这些脚本我一行都写不出来，但「要什么」是我说的。

---

用了差不多两个月。每周一两张主视觉是它出的。
